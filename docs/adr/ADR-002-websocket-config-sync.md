# ADR-002：使用 WebSocket 进行配置同步推送

## 状态

已采纳

## 背景

网关集群部署时，管理后台修改配置后需将变更实时推送至所有网关实例。候选方案：

1. **WebSocket 长连接推送**：服务端主动推送，延迟低（≤ 3s），实现简单
2. **消息队列（MQ）**：通过 Kafka/RabbitMQ 广播配置变更，可靠性高，但引入新中间件
3. **纯轮询**：网关实例定时轮询数据库，实现最简，但延迟高（30s+）

## 决策

采用 WebSocket 长连接推送 + 30s 兜底轮询的混合方案。

## 理由

- **低延迟**：WebSocket 推送延迟 ≤ 3s，满足配置推送生效时间目标
- **轻量**：不引入 MQ 中间件，减少运维复杂度和部署依赖
- **可靠性兜底**：30s 轮询比对 config_version 防止推送丢失，双重保障
- **V1.0 规模适配**：网关实例数 ≤ 10 时，WebSocket 推送足够可靠

## 后果

- **正面**：架构简单，无额外中间件依赖，推送延迟低
- **负面**：WebSocket 非保证投递（vs MQ 的持久化），需兜底轮询补偿；管理后台为推送源，单实例为 SPOF
- **风险**：集群规模 > 50 实例时，WebSocket 连接数和推送并发可能成为瓶颈，届时需迁移至 MQ 方案
- **缓解**：推送失败 3 次重试 + 30s 兜底轮询 + 大盘告警，确保最终一致性
