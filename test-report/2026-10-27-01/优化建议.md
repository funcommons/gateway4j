# Gateway4j 管理后台 —— 体验优化建议书

> 评审对象：gateway4j 管理控制台（Vue 3 + Element Plus + Fc\* SDK）
> 参考基线：Kong Manager、Apache APISIX Dashboard、Argo CD、Nacos Console、Traefik Dashboard、阿里云网关控制台
> 评审方式：全量业务线 Playwright 回归（9 条业务线 / 79 条用例）+ 源码走查
> 报告日期：2026-10-27

---

## 0. 结论先行

本次回归在**功能层**没有发现崩溃级事故，但发现了一个贯穿全站的**外壳级缺陷**：管理后台的**侧边栏与顶栏从未被渲染**，导致**用户没有任何可见的导航入口，也没有任何可见的退出登录入口**。同时，`FcFilterBar` 缺少 `actions` 插槽，使**所有列表页的「新建 / 导入」主操作按钮全部消失**。

这两点叠加的后果是：当前版本的后台**不是一个"操作效率低的工具"，而是一个"必须知道 URL 才能用的半成品"**。所有业务线功能（路由、插件、画布、导入导出）本身是可用的，但用户无法通过界面抵达它们。

因此本次建议分为两条主线：

| 主线 | 目标 | 优先级 |
|---|---|---|
| **A. 把外壳装回去**（P0） | 恢复导航骨架、补齐主操作入口、统一权限码词表 | 立即 |
| **B. 把体验做到大厂水位**（P1/P2） | 信息架构、布局密度、交互细节、空/错/载三态规范 | 迭代 |

下文第 1 章为 P0 止血项，第 2 章起为按大厂标准展开的体系化建议。

---

## 0.1 先修契约，再谈体验（回归中发现的 5 个"静默失败"）

体验优化有一个前提：**操作必须真的会生效**。本轮回归发现 5 处**静默失败**——用户点了、界面给了成功反馈、但事情没做成。这类问题对信任的伤害远大于任何视觉瑕疵，因此必须排在体验优化之前：

| 契约 | 现状 | 用户看到的 | 建议 |
|---|---|---|---|
| **确认弹窗返回值** | `useFcConfirm` 的 `confirm()` **永远 resolve(false)** | 弹窗关闭、**什么也没发生** | 修正 resolve 时序，并让「确认」与「取消」可区分 |
| **表单校验返回值** | 路由表单把校验失败吞成布尔值，父组件忽略返回值 | **「保存成功」+ 脏数据入库** | 校验失败必须抛错或被父组件显式检查 |
| **画布保存载荷** | 前端发对象、后端收字符串 | **「已自动保存」+ 数据从未落库** | 统一契约 + 保存后回读校验，落库失败必须报错 |
| **插件 Schema 类型** | 后端 `config_schema` 是 JSON **字符串**，前端按**对象**取属性 | 配置弹窗恒显示**「暂无 schema」** | 后端改结构化返回，或前端 `JSON.parse` 后使用 |
| **分页元数据类型** | 后端 `Long` 转字符串，前端直接透传 | **分页控件整体不渲染** | 前端 `Number(total)` 归一，并修正 `Page<T>` 的类型声明 |

**共同规律**：这 5 个问题都源于**前后端/父子组件之间的契约没有被断言**。建议引入一条硬规则：

> **凡跨边界传递的结构化数据，必须有"契约测试"兜底 —— 接口用 OpenAPI 快照 diff，组件用 slot/prop 契约测试，类型用运行时归一 + 编译期约束。**

大厂在这方面的通行做法是 **Schema First + Consumer-Driven Contract Testing**：先由 OpenAPI/JSON Schema 定义契约，再由消费方（前端）生成类型与 Mock，最后在 CI 里做双向 diff。本项目的 `PluginDynamicForm` 恰好是 **JSON Schema 驱动**的 —— 这套机制本该是强项，却因为 schema 的**序列化形式**没对齐而整体失效。

## 1. P0 止血项（阻塞级，建议本周内修复）

### 1.1 恢复全局导航外壳

**现状**
`src/layouts/MainLayout.vue` 通过具名插槽向 `FcMain` 注入侧边栏与顶栏：

```vue
<FcMain>
  <template #sidebar> <FcSidebar …>…</FcSidebar> </template>
  <template #header>  <FcHeader  …>…</FcHeader>  </template>
  <router-view />
</FcMain>
```

但 `src/components/layout/FcMain.vue` 的模板只有一个默认插槽：

```vue
<main class="fc-main">
  <slot> …默认 router-view… </slot>
</main>
```

Vue 3 中**没有匹配到出口的具名插槽会被静默丢弃**（不报错、不警告）。结果：`FcSidebar` / `FcHeader` 从未进入 DOM，`.fc-sidebar`、`.fc-header` 在页面上完全不存在。

**实测影响（回归证据见 `screenshots/01-auth/`）**

| 丢失能力 | 用户后果 |
|---|---|
| 侧边栏 9 个业务线入口 | 无法在模块间切换，只能手敲 URL |
| 顶栏「退出」按钮 | **无法退出登录**（`auth.logout()` 代码存在但没有触发点） |
| 顶栏主题 / 品牌 / 语言切换器 | 无法切换主题与中英文 |
| 顶栏折叠侧栏 / 用户信息 | 无用户身份感知，无折叠 |

**建议**

1. **方案一（推荐，SDK 语义更正）**：给 `FcMain` 补齐 `sidebar` / `header` / `footer` 三个具名插槽，模板改为：

   ```vue
   <div class="fc-shell">
     <aside v-if="$slots.sidebar" class="fc-shell__aside"><slot name="sidebar" /></aside>
     <div class="fc-shell__body">
       <header v-if="$slots.header" class="fc-shell__header"><slot name="header" /></header>
       <main class="fc-main"><slot /></main>
     </div>
   </div>
   ```
   同时保留 `FcMain` 的 `router-view` 默认行为，二者兼容。

2. **方案二（若不想动 SDK）**：`MainLayout` 改为直接使用 `FcSidebar` + `FcHeader` + 内容区三段式布局，把 `FcMain` 降级为纯内容容器。

3. **必须加的防回归护栏**（本次缺陷逃逸的根因）：
   - **组件契约测试**：对每个 SDK 组件断言"声明了哪些 slot"，并在 `MainLayout` 侧断言"使用的 slot 名都在 SDK 中存在"，一旦不匹配立即失败；
   - **E2E 冒烟**：首屏必须存在 `.fc-header` 与 `.fc-sidebar`，否则 CI 直接红。

> 大厂做法：Ant Design / Element Plus 这类组件库在文档里把 slot 列表当作**公开契约**；AntD 甚至有 `slots` 的 TypeScript 泛型约束，写错 slot 名会在编译期报错。本项目既然自研 SDK，更应该把这条约束补上。

### 1.2 补齐列表页主操作按钮（`FcFilterBar.actions`）

**现状**
`src/components/navigation/FcFilterBar.vue` 只有默认插槽，而路由列表、用户列表都把主按钮写在 `#actions` 里：

```vue
<FcFilterBar>
  …筛选控件…
  <template #actions>
    <FcButton variant="primary" @click="onNav('/routes/new')">新建</FcButton>
    <FcButton variant="secondary" @click="onNav('/import-export')">导入</FcButton>
  </template>
</FcFilterBar>
```

实测 `FcFilterBar` 的 DOM 子节点只有：5 个状态筛选按钮 + 1 个分隔线 + 1 个搜索输入框。**`#actions` 内容全部丢失**。

**影响**：路由列表的「新建」「导入」、用户列表的「新建」——所有**创建类主操作**在界面上不存在。用户只能靠"猜 URL"或"导入导出页的 tab"绕行。

**建议**

1. 给 `FcFilterBar` 增加 `actions` 具名插槽，并在布局上**右对齐**（大厂后台的通用范式：左侧筛选、右侧主操作）：

   ```vue
   <div class="fc-filter-bar">
     <div class="fc-filter-bar__filters"><slot /></div>
     <div v-if="$slots.actions" class="fc-filter-bar__actions"><slot name="actions" /></div>
   </div>
   ```

   ```scss
   .fc-filter-bar { display: flex; justify-content: space-between; align-items: center; gap: 12px; }
   .fc-filter-bar__actions { margin-left: auto; display: flex; gap: 8px; }
   ```

2. 同步补齐 `FcSection` / `FcSectionHeader` 是否也需要 `actions` 插槽（当前 `FcSectionHeader` 是否有额外插槽请一并核对，避免同类问题）。

3. 把「组件声明的 slot 列表」做成**单一事实来源**（如 `slots.json` 或从 SFC 解析生成），SDK 组件测试与页面测试共用。

### 1.3 统一权限码词表（RBAC 模型对齐）

**现状** —— 前端与后端用了**两套互不相交的权限码**：

| 前端使用位置 | 前端拼出的码 | 后端 `gw_permission` 里是否有 |
|---|---|---|
| `canEdit('route')` | `route:edit` | ✅ 有 |
| `canEdit('plugin')` | `plugin:edit` | ✅ 有 |
| 路由守卫 `/dashboard` | `monitor:read` | ✅ 有 |
| 路由守卫 `/users`、`/settings` | `system:user` | ✅ 有 |
| 路由守卫 `/roles` | `system:role` | ✅ 有 |
| **`canEdit('user')`** | **`user:edit`** | ❌ **无** |
| **`canEdit('system')`** | **`system:edit`** | ❌ **无** |
| **侧边栏用户/角色入口** | **`user:read`** | ❌ **无** |

**实测后果**

- **用户管理模块整体只读**：行内「编辑 / 禁用 / 重置密码 / 删除」全部被 `v-if="canEdit('user')"` 隐藏，`/users` 页面**一个按钮都没有**（实测 `document.querySelectorAll('button').length === 0`）。
- **系统设置无保存按钮**：`canEdit('system')` 为 false，通用设置与安全设置两个 Tab 只能看不能存。
- 侧边栏即便修好，`hasPermission('user:read')` 仍为 false → 用户管理/角色权限入口**依然不显示**。

**建议（采用大厂成熟的 RBAC 资源-动作模型）**

1. 权限码规范化为 **`{资源}:{动作}`**，动作枚举收敛为：`read / create / update / delete / publish / operate / manage`。
2. 前端 `canEdit(resource)` 的语义**收敛为单一动作**，不要让一个函数名覆盖多种语义：

   ```ts
   const can = (resource: string, action: Action) => hasPermission(`${resource}:${action}`)
   can('route', 'update')      // route:update
   can('user',  'update')      // user:update
   can('system','update')      // system:update
   ```

3. 同步补齐种子数据（`V1.1.0__seed_demo_data.sql`），至少补齐：

   | 权限码 | 名称 | 类型 |
   |---|---|---|
   | `user:read` / `user:create` / `user:update` / `user:delete` / `user:reset-password` | 用户管理 | MENU + BUTTON |
   | `system:read` / `system:update` | 系统设置 | MENU + BUTTON |
   | `role:read` / `role:manage` | 角色权限 | MENU + BUTTON |
   | `route:publish` | 发布/下线 | BUTTON（已有） |

4. **加一道启动期自检**：前端拉取 `/v1/permissions` 后，与代码里用到的权限码常量做一次差集检查，发现"前端引用了但后端不存在"的码就在控制台告警 + 上报监控，避免再次静默失效。

> 大厂做法：阿里云 / 腾讯云控制台普遍用 `acs:ram:CreateInstance` 这类**资源-动作**码，并在前端维护一份**权限码字典**（`permissionMap`），组件只声明"我需要什么权限"，由框架统一解析和按钮级鉴权，避免每个页面手拼字符串。

### 1.4 补齐缺失的后端接口

| 缺失接口 | 前端调用方 | 现象 | 建议 |
|---|---|---|---|
| `GET /v1/routes/{id}` | `src/api/routes.ts` `getRoute()` | **405 Method Not Allowed**（后端只有 PATCH / DELETE），编辑任何已有路由页直接报「加载失败：支持的方法: [DELETE, PATCH]」 | 补 `@GetMapping("/{id}")`，返回 `RouteDetail` + conditions + bindings + chain 聚合视图 |
| `GET/PUT /v1/config/{type}` | `src/api/misc.ts` `getConfig()/saveConfig()` | **404**，系统设置通用/安全两个 Tab 全部不可用 | 新增 `ConfigController`，落库到 `gw_config`（可复用 `gw_config_push_log` 的推送通道做热更新） |
| `POST/PUT/DELETE /v1/roles`、`PUT /v1/roles/{id}/permissions` | 角色权限页（目前无 UI） | 后端 `RbacController` 只有两个 GET | 补齐角色 CRUD 与授权写接口，才能做角色授权界面 |

### 1.5 补齐服务端校验（与前端对齐）

实测 `POST /v1/routes` 对以下输入**全部返回 200 并入库**：

```jsonc
{ "route_name": "bad name zz", "route_type": "BACKEND",
  "path": "not-a-path", "upstream_url": "ftp://xxx", "sort_order": 1 }
```

前端有 `^[a-zA-Z0-9_]{2,50}$` / `^\/[^\s]+$/` / `^https?:\/\/\S+$` 三条正则，后端**一条都没有**。任何绕过前端的调用（导入包、开放 API、脚本）都会写入脏数据。

**建议**：在 `RouteService` / `PluginService` / `UserService` 的写方法入口加 Bean Validation（`@Pattern` / `@NotBlank` / `@Size`），错误统一走 `ApiCode.PARAM_ERROR` 返回**字段级错误**（前端 `mapFieldErrors` 已经具备这个能力，但后端从未下发过字段级错误）。

### 1.6 统一错误提示文案，禁止透出后端原始报文

当前界面上会直接出现：

- 「请求资源不存在」（404，`ApiCode.RESOURCE_NOT_FOUND`）
- 「加载失败：支持的方法: [DELETE, PATCH]」（405，Spring 原始报文）
- 「系统繁忙，请稍后重试」（10001，实为**参数校验失败**被归到了通用错误）

**建议**

1. 前端 `http.ts` 拦截器建立**错误文案映射表**：`ApiCode` → 用户可读文案 + 是否可重试 + 建议动作；未知码兜底为「操作失败，请稍后重试」并把 `trace_id` 放进"复制详情"里，**不要直接展示**。
2. 后端把「参数校验失败」从 10001 拆到 `PARAM_ERROR`（10002 之类），并下发 `field_errors`。
3. 网络层 5xx 与业务层 4xx 视觉分层：业务错误用 warning 色，5xx 用 danger 色并提供「重试」按钮。

### 1.7 建立「操作必须生效」的契约护栏

针对第 0.1 节的 5 个静默失败，建议一次性补齐护栏，而不是逐个打补丁：

| 边界 | 护栏 | 落地方式 |
|---|---|---|
| 组件 ↔ 组件（slot / prop） | **slot 契约测试** | 解析 SFC 提取「已声明 slot 清单」，断言页面使用的 slot ⊆ 清单；不匹配即 CI 红 |
| 前端 ↔ 后端（接口） | **OpenAPI 快照 diff** | 后端导出 OpenAPI，前端 CI 校验 `api/*.ts` 里的 URL/方法均存在且 method 一致 |
| 前端 ↔ 后端（数据类型） | **运行时归一 + 编译期类型** | 在 `http.ts` 统一把分页元数据转数字；`Page<T>` 类型与运行时一致（TS 才拦得住） |
| 前端 ↔ 后端（JSON Schema） | **schema 消费方契约** | `PluginDynamicForm` 对 `config_schema` 做 `typeof === 'string' ? JSON.parse() : x` 兼容，并加一条"schema 有属性 ⇒ 必须渲染出表单控件"的测试 |
| 权限码 | **差集检查** | 前端引用的权限码与 `/v1/permissions` 求差集，有差集即启动告警 + 上报监控 |

## 2. 信息架构（IA）与导航体系

### 2.1 目标导航结构

大厂网关控制台通常把"**对象**"和"**运行时**"分开。当前 9 个入口平铺在一个侧边栏里，缺少层次。建议改为**分组 + 可折叠**（`FcSidebarNav` 已支持 `FcNavGroup`，直接用）：

```
网关配置
  ├─ 路由管理          /routes
  │    ├─ 路由列表      /routes
  │    ├─ 编排画布      /canvas          ← 提升为一级"画布工作台"
  │    └─ 导入导出      /import-export
  └─ 插件管理
       ├─ 插件列表      /plugins
       ├─ 全局插件      /plugins/global
       └─ 内置插件      /plugins/builtin

运行观测
  ├─ 监控大盘          /dashboard
  └─ 路由状态          /dashboard?tab=status

系统管理
  ├─ 用户管理          /users
  ├─ 角色权限          /roles
  └─ 系统设置          /settings
```

### 2.2 三级面包屑 + 页面标题

当前只有 `FcSectionHeader`（一级标题），缺面包屑。**大厂范式**：顶栏下方一行 `配置中心 / 路由管理 / 编辑路由`，点击可回退。

- 复用现有 `FcSectionHeader`，增加 `breadcrumb` prop；
- 路由守卫的 `meta` 里补 `titleKey`（已有）+ `breadcrumb` 数组，标题与面包屑**从路由元数据统一推导**，杜绝每个页面各写一份。

### 2.3 全局搜索（⌘K）

Kong / Argo CD / Nacos 都有全局命令面板。建议在顶栏 `FcHeader` 的 `search` 插槽（SDK 已预留！）放一个全局搜索：
- 搜路由 / 插件 / 用户，⌘K 唤起，↑↓ 选择，Enter 直达；
- 支持最近访问（recently visited）与快捷动作（新建路由、启用插件）。

> 注意：`FcHeader` 的 `search` 插槽目前也没被 `MainLayout` 使用 —— 修外壳时可以顺带落地。

## 3. 布局与视觉（比肩大厂）

### 3.1 三段式 Shell 尺寸规范

| 区域 | 当前 token | 建议 | 依据 |
|---|---|---|---|
| 顶栏高 | `--app-header-height: 60px` | **56px** | Ant Design Pro / Arco Pro / Kong 均为 56–60，56 更紧凑 |
| 侧边栏宽 | `--app-sidebar-width: 220px` | **232px**（折叠 **56px**） | Arco Pro 220、Kong 240；232 容纳中文 4 字 + 图标 |
| 内容区留白 | 无 token | **24px**（页面级）/ **16px**（卡片内） | 大厂后台标准 24px 栅格 |
| 内容最大宽 | 无限制 | **流式**（表格页不限宽，表单项限 `max-width: 960px`） | 长表单行太长会降低可读性 |

建议补齐 token：

```scss
--app-content-padding: 24px;
--app-content-padding-sm: 16px;
--app-card-padding: 20px;
--app-form-max-width: 960px;
--app-table-row-height: 44px;      /* 紧凑态 36px / 默认 44px / 宽松 52px */
--app-z-header: 1000; --app-z-drawer: 1100; --app-z-modal: 1200;
```

### 3.2 表格页布局范式

大厂表格页统一是：**标题栏（含描述 + 主操作）→ 筛选工具栏 → 表格 → 分页**。当前项目已经有 `FcSection` + `FcFilterBar` + `FcTable` + `FcPagination`，骨架是对的，问题在：

1. **主操作按钮应与页面标题同右侧**，而不是挤在筛选栏里（筛选项多时按钮会被挤走）。
   ```
   ┌─────────────────────────────────────────────────────────┐
   │ 路由管理                          [导入] [＋ 新建路由]   │  ← 标题行
   │ 12 条路由 · 3 条草稿                                     │
   ├─────────────────────────────────────────────────────────┤
   │ [全部][草稿][已发布] │ 搜索路由名 🔍        密度 ⌗  列 ⚙ │  ← 工具栏
   ├─────────────────────────────────────────────────────────┤
   │ 名称       类型   路径        状态    最后更新    操作   │
   │ …                                                     │
   └─────────────────────────────────────────────────────────┘
   ```
2. **表格右侧固定操作列**目前 `fixed="right" width="320"`，320px 太宽且操作按钮是文字链，建议：
   - 操作列宽收到 **120–160px**，超出收纳进「⋯」下拉菜单；
   - 行内最多放 2 个高频动作（编辑 / 发布），其余进菜单 —— 这是表格操作的标准收敛范式（AntD Pro / GCP Console 都是这个模式）。
3. **状态列用彩色标签 + 圆点**（当前 `FcStatusBadge` 已具备），但应统一语义色：
   | 语义 | 状态 | 色 |
   |---|---|---|
   | 成功 | 已发布 / 已启用 / 健康 | green |
   | 草稿 | 草稿 | neutral |
   | 进行中 | 变更中 / 发布中 | blue + loading |
   | 危险 | 错误 / 熔断 | red |
   | 警告 | 已下线 / 已禁用 | orange |

### 3.3 表单页布局范式

路由编辑器的四个 Tab（基本信息 / 分发条件 / 插件绑定 / 插件链）建议改成**左表单右摘要**（1600px 宽屏下几乎所有成熟网关后台都是这个布局）：

```
┌──────────────────────────────┬────────────────────────┐
│ 基本信息                       │  路由摘要              │
│  路由名称  [____________]      │   类型   分发路由       │
│  路由类型  [后置|分发]          │   路径   /api/**        │
│  匹配路径  [____________]      │   上游   http://…        │
│  后端地址  [____________]      │   状态   ● 草稿          │
│  排序      [  1 ]  描述 [__]  │   插件   3 个            │
├──────────────────────────────┤   条件   2 条            │
│              [取消] [保存]     │                        │
└──────────────────────────────┴────────────────────────┘
```

右侧摘要让用户在编辑时始终掌握全局状态（Ant Design Pro 表单页、Kong 路由详情抽屉都是这个套路）。

### 3.4 画布工作台的取景

`/routes/:id/canvas` 是本产品的**核心竞争力页面**，但当前体验偏"玩具级"。建议：

- **画布默认自适应**：`fit-view-on-init` 已有，但节点多时没有缩放级别限制；加 `min-zoom/max-zoom`（0.3–2）与「适应画布 / 100%」按钮组（Vue Flow `Controls` 已挂载，可定制）。
- **空画布必须有引导**：当前空画布是**纯空白**（实测 `.canvas-shell` 文本长度为 0）。应给出居中空态卡：
  ```
        ┌───────────────────────────┐
        │      [流程图 icon]         │
        │   还没有编排任何节点        │
        │  从左侧拖入「分发路由 / 后置路由 / 插件节点」│
        │           [ 从路由树生成 ]  │
        └───────────────────────────┘
  ```
  并提供「**从路由树一键生成画布**」按钮 —— 见 4.3。
- **组件面板可搜索**：节点类型多了以后左侧面板要支持搜索过滤（当前 3 种还不够，但内置插件节点一多就会爆）。
- **属性面板分组**：节点属性按「基础 / 路由 / 插件配置」折叠分组，避免长表单。

## 4. 功能合理化

### 4.1 路由管理：缺失的关键能力

| 能力 | 现状 | 建议 |
|---|---|---|
| 路由详情接口 | 缺 `GET /{id}` → **无法编辑任何已有路由** | 补接口（1.4） |
| 路由复制/另存为 | 无 | 大厂必备：Kong「Duplicate」、APISIX「Clone」 |
| 路由批量操作 | 无 | 多选 + 批量发布/下线/删除/改标签 |
| 路由标签/分组 | 无 | 多项目多环境时必需（`env=prod`、`team=pay`） |
| 路由 diff / 版本对比 | 无 | 配置变更审计（`gw_config_push_log` 已有表，前端未暴露） |
| 路由健康检查 | 无 | 发布前校验 upstream 可达性 |
| 灰度 / 权重 | 无 | 分发路由应支持按权重分流（Kong / APISIX 都有） |
| 路由复制粘贴导出 | 仅整包导出 | 支持单条复制 JSON（运维高频） |

### 4.2 插件管理：缺失的关键能力

| 能力 | 现状 | 建议 |
|---|---|---|
| 插件健康/调用指标 | 无 | 插件链上每层应有 QPS / 错误率 / P99（Kong / Envoy 都展示） |
| 插件配置版本与回滚 | 无 | 配置变更可 diff、可回滚 |
| 插件依赖图 | 无 | 「安全插件 → 限流插件」的依赖拓扑（类似 Argo CD 的资源图） |
| 插件市场 / 模板 | 无 | 内置插件应有「一键启用 + 示例配置」 |
| 插件作用域说明 | 字段有，无解释 | 「路由级 / 全局」作用域在 UI 上需 tooltip 说明差异 |

### 4.3 画布与路由树的数据同源（重要）

实测：`gw_route_canvas.canvas_data` 对从未在画布编辑过的路由是 `{}`，**画布不会由路由树自动生成**。结果是：

- 分发路由 `api_gateway` 在列表里有 4 个子路由，但画布上**空空如也**；
- 用户在列表里改了路由结构，画布**不会跟着变**；
- 用户在画布里连了边，列表里的树**也不会变**；
- 「路径预览」又是**按路由树算的** → 画布与预览本身就自相矛盾。

**建议**：确立**路由树为唯一事实源 (Single Source of Truth)**，画布是它的一个视图：

1. 画布加载时，若 `canvas_data` 为空 → **自动从路由树生成**（分发路由 → DISPATCH 节点，子路由 → BACKEND 节点，父子关系 → 连线）；
2. 画布保存时 → **反向回写**路由树（`parent_route_id` / 条件 / 插件绑定），或明确提示"画布为只读可视化视图，编辑请回到路由列表"；
3. 二选一，但**不能维持现状**（现状是"两个都能编辑但互不相干"，是数据一致性事故的温床）。

### 4.4 导入导出：形成闭环

当前导出只能导出"勾选的路由"，导入只能导入整包 JSON。建议补齐大厂标准的**配置迁移三件套**：

1. **导出选装**：可选导出范围（单路由 / 整棵子树 / 按标签 / 全部）、可选格式（JSON / YAML）、可选是否含插件与条件；
2. **导入预检可视化**：当前预检报告只给「可导入：否」且**不给原因**（非法 JSON、结构缺 `routes` 都不提示）。应做成 **Diff 视图**：
   ```
   路由名        操作        原因
   e2e_rt_1      新增        ✔
   payment_svc   覆盖        上游地址变更 http://a → http://b
   user_svc      跳过        策略=跳过
   ```
3. **导入回滚**：导入前自动快照，失败可一键回滚（Kong / Nacos 的配置导入都有）。

### 4.5 用户与角色：补齐授权闭环

- 角色权限页目前**纯只读**，且 4 个种子角色里**只有 ROLE_ADMIN 有权限绑定**，`ROLE_OPS` / `ROLE_DEV` / `ROLE_GUEST` 是空授权 —— 建了角色却什么都干不了，用户会直接困惑。
- 建议补：角色 CRUD + **权限树勾选 UI**（按 `资源 → 动作` 两级树，父节点半选）+ 角色成员管理 + 「复制角色」+ 「角色权限 diff」。
- 用户列表补：**角色分配可视化**（当前 `FcTag` 只显示角色名，改密/禁用无二次确认弹窗文案区分）。

### 4.6 审计与可观测

项目已引入 framework4j 审计（`@Auditable` + Hash Chain），但**界面上完全看不到**。建议在路由/插件变更处展示：
- 「谁在什么时候改了什么」的**变更时间线**（配置中心页）；
- 顶部**告警中心**（Webhook 推送失败的配置变更、路由熔断）。

### 4.7 幂等与并发编辑

- 写操作已用 `Idempotency-Key`，**建议在 UI 层补齐**：危险操作（删除/覆盖）自动携带幂等键，避免用户手快双击产生两次删除（虽然后端幂等，但 UI 应给出「处理中」锁）。
- **乐观锁**：路由 / 插件配置建议加 `config_version` 比对（表里已有 `config_version` 字段，前端未使用），两人同时编辑时提示「已被他人修改」。

## 5. 交互细节（细节仿大厂）

### 5.1 空 / 错 / 载 三态规范

大厂后台的硬性要求：**任何数据区都必须有这三态**，且三态视觉层级清晰。

| 状态 | 当前 | 建议 |
|---|---|---|
| 加载中 | 部分页面有 `FcSkeleton`，覆盖不一致（路由列表有、用户列表有、插件列表有、看板指标区没有） | 全站统一：表格 6 行骨架、卡片 3 张骨架、图表区域骨架遮罩；**禁止**用整页 loading |
| 空态 | `FcEmpty` 已有，但**文案没有行动指引** | 空态必须含「为什么空 + 下一步做什么 + 一个主按钮」。例：路由列表空 → 「还没有路由」+「创建第一条路由」+「从模板导入」 |
| 错误 | 直接透出后端报文 | 见 1.6；错误态要含「原因 + 建议 + 重试按钮 + trace_id 复制」 |

### 5.2 表格细节

1. **列设置**：用户可自选显示列、调整顺序、记忆偏好（存 localStorage）。`FcTable` 已支持 `columns` 声明式，加列设置即可。
2. **密度切换**：紧凑 / 默认 / 宽松三档（Kong、Argo CD 都有），表格行高 36/44/52。
3. **排序**：默认列支持点击排序，并在表头显示升降箭头；当前排序状态要有视觉反馈。
4. **数字右对齐 + 等宽数字**：排序值、请求数、错误率、耗时这类列应右对齐并使用 `font-variant-numeric: tabular-nums`（当前所有列都是左对齐，扫读体验差）。
5. **ID 可复制**：路由 ID / 插件标识这类长串应「等宽字体 + hover 出现复制按钮」。
6. **相对时间**：列表里的 `updated_at` 显示「3 分钟前」，hover 显示完整时间戳（Kong / GitHub 范式）。当前直接显示 ISO 字符串或时间戳，可读性差。
7. **长文本截断**：描述列超长时省略号 + hover 全文 tooltip。

### 5.3 表单细节

1. **校验时机**：当前必填校验在 **blur** 触发，提交时才全量显示 → 用户填完一屏才被告知一堆错。建议：
   - blur 时校验单字段（现状可以）；
   - 提交时聚焦**第一个**错误字段并滚动定位（当前不定位）；
   - 顶部展示错误汇总条（AntD Pro 范式）。
2. **字数统计**：`route.remark` 有 `maxlength=200`，但没开 `show-word-limit`（插件描述开了，用户描述没开）—— 统一都开。
3. **危险字段标注**：上游地址、路径这类会影响生产的字段，加"改动后需重新发布"的提示。
4. **表单 dirty 保护**：离开有未保存修改时确认（代码里有 `unsavedChanges`，需覆盖全部编辑页）。
5. **下拉搜索**：路由 200+、插件 100+ 时，父路由选择、插件绑定选择必须可搜索（`FcSelect` 已有 `remote`/`filterable` 能力，需启用）。

### 5.4 反馈与撤销

大厂后台的黄金实践：**Toast 里带「撤销」**，而不是只弹「操作成功」。

- 删除路由 / 禁用插件 / 下线路由后 → Toast「已下线」+「撤销」按钮（后端需提供反向接口，删除类要支持软删 + 恢复窗口）。
- 所有操作 Toast 统一位置（右上角）、统一时长（成功 3s / 失败常驻）、统一文案句式（动宾结构）。
- 加载态：按钮进入 loading 后**必须禁用**，防重复提交（框架4j 已有幂等，但 UI 仍应锁）。

### 5.5 可访问性（A11y）

- 侧边栏导航要有 `aria-current="page"`，当前选中项仅靠颜色区分；
- 图标按钮必须有 `aria-label`；
- 焦点态可见（`:focus-visible` 描边），当前 Element Plus 默认样式可能被覆盖；
- 表单错误用 `aria-describedby` 关联；
- 弹窗打开时焦点移入、关闭时归还（Element Plus 已支持，需验证 FcDialog 未破坏）。

### 5.6 响应式与显示密度

- 1366×768（主流笔记本）下，路由列表 6 列 + 操作列会横向滚动 → 低优先级列在窄屏隐藏；
- 1920/2560 宽屏下表格拉伸过度 → 限制内容 `max-width` 或让表格列自适应；
- `FcSidebar` 已有 `useResponsive` 移动端折叠能力，但**因为外壳没渲染而完全没生效**。
