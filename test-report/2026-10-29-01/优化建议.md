## 2. 分级建议

> 每条含：现状（已核实）→ 对标参照 → 建议方案 → 工作量。P0=下一迭代必须完成；P1=当前季度；P2=平台化与纵深。

### 2.1 P0（三项，均已在 0.1 节给实据）

#### P0-1 摘除 9300 上的管理面：数据面端口无鉴权暴露全量 admin API

**现状**：见 0.1-3。要点复述：9300 实测 `/v1/users` 200 且响应含 **bcrypt password 哈希**，`/v1/routes`/`/v1/plugins`（含 PATCH/DELETE/enable/disable）等约 70 个端点可匿名读写；`/v1/open/**` 的签名防护在 reactive 端同样失效（SignatureAutoConfiguration 仅 Servlet）；且同一接口两端口**序列化契约不一致**（9301 的 Long 按框架契约序列化为字符串——`http.ts:85` 注释自证；9300 WebFlux 不走 MVC Jackson 定制，返回数字，实测同一 monitor 接口 9301 timestamp 为 `"1793210495939"`、9300 为 `1793210333587`）。另 `upload-jar` 用 Servlet MultipartFile（`PluginController.java:127`）在 reactive 下参数无法解析——admin Controller 本就不该在 9300 存活。9300 还顺带暴露 `static/fu-autofill.js`、`fu-security-watermark.js`。

**对标**：APISIX 的 Admin API（默认 9180）只绑 localhost/内网，与数据面 9080 物理分离；Kong Admin（8001）与代理流量（8000/8443）分离且可绑定 127.0.0.1；"数据面进程不带管理 API"是三类主流网关的一致行规。序列化契约一致性对标：Apiarity/OpenAPI diff 类护栏的"同端点同 schema"原则。

**建议**（两步，第一步即消除风险面）：
1. **结构性摘除（M）**：把 `admin.mapper` 下沉为独立持久层模块（或并入 gateway4j-common），engine/gateway-boot 只依赖持久层；gateway-boot 删除 `gateway4j-admin` 依赖与 `@MapperScan("...admin.mapper")`，组件扫描自然不再有 admin Controller。风险面一次性归零，同时顺带解决双端口契约分裂与 upload-jar 假端点。
2. **过渡兜底（S，可与 1 同迭代）**：若暂不能动依赖，先 (a) 收窄 `scanBasePackages` 排除 `admin.controller`（mappers 保留）；(b) 给 9300 加一个 reactive `WebFilter` 校验 Bearer（framework4j 缺 reactive 实现先自写最小实现，或仅允许 `/v1/auth/login` 与业务转发路径）；(c) 部署态将 9300 管理路径绑定内网。并向 framework4j 上报 reactive 版 `@RequiresToken` 缺口（验收报告已定性"框架层缺口"）。

**验收**：`curl http://localhost:9300/v1/users` 返回 401/404；契约护栏新增一条"9300 与 9301 对同一路径返回一致 schema"。

#### P0-2 大盘呈现正确性：13 个 0 / Invalid Date / AM-PM

**现状**（截图 `screenshots/02-dashboard/02-01、02-12`，像素级核验为 **13 个 0** = 初始 0 + 12 条路由各拼一个）：
- **总请求数显示 `0000000000000`**：framework4j-web 契约 Long→字符串（`http.ts:85` 注释"后端 Long 统一序列化为字符串 (framework4j-web 契约)"），前端 `Index.vue:173` `statuses.reduce((s, r) => s + (r.total_requests || 0), 0)` 对字符串做 `+` 退化为拼接；`D18` 修复只为分页四键做了 Number 归一（`http.ts:88-103`），metrics 载荷没人管。
- **趋势图 X 轴整排 `Invalid Date`**：`Index.vue:289` `new Date(p.timestamp)`，timestamp 按契约到达时是字符串 `"1793..."`，`new Date("1793210000000")` → Invalid Date（纯数字串按年份解析越界）。
- **最近刷新 `1:31:28 AM`**：`Index.vue:265` `new Date().toLocaleTimeString()` 随浏览器 locale 走英文 12 小时制，与全站中文矛盾。

**对标**：Grafana/阿里云监控对数值列一律显式类型化 + `tabular-nums` 渲染；图表时间轴由图表库统一格式化（ECharts `time` 轴类型自带 formatting），不存在"Invalid Date"上屏的可能——这类问题在大厂看板属于 P0 级"监控可信度"缺陷（运维第一眼看到 0000000000000 就会永远不再信任这块屏）。

**建议（S）**：
1. `http.ts` 归一层扩展：对 metrics 形状载荷（`data_points[]`/`routes/status[]`）把 `total_requests/error_count/error_rate/active_connections/timestamp` 归一为 Number（复用 `normalizePagination` 的写法抽一个 `normalizeNumericFields(payload, keys)`）；
2. `Index.vue:289` 时间戳优先让后端输出 ISO-8601（`MonitorController.java:69` 改 `Instant.ofEpochMilli(...).toString()`，带时区且 `new Date(iso)` 直解，顺带修 API 语义）；过渡期前端 `new Date(Number(p.timestamp))`；
3. `lastRefresh` 用 `dayjs().format('HH:mm:ss')`（项目已有 `src/utils/index.ts formatDate` 同风格）；
