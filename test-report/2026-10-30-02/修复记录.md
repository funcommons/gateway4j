## SDK 层缺陷三连（修复过程中揪出，均已修 + 有回归守护）

1. **FcInput `rows` 声明但从未绑定**（C 上报）：发布弹窗 3 行/导入 JSON 框 12 行全部塌成 2 行。修复：`:rows="rowsBound"`（computed 归一 number）。回归：FcInput.rows.test.ts 3 例。
2. **FcFormItem 压死 el-form 校验展示**（首轮 e2e 03-07/06-08 失败，真实浏览器逐绑定二分定位）：
   - `withDefaults` 给 `required` 默认 `false` → 模板静态 `:required="false"` → EP 语义「未传才从 rules 推导必填」被压死；
   - 静态 `:error="undefined"` → EP 的 error watcher 把校验态重置回 validating（DOM 实锤卡 `is-validating`）；
   - **再叠一层 Vue Boolean prop 转型**：`required?: boolean` 未传时运行时是 `false` 不是 `undefined`，任何「undefined 才下发」的守卫对 Boolean 无效。
   - 修复：**`required` 从 Props 声明中移除**（走 attrs 透传，显式传参照常生效），`error` 改条件下发；注释写明三层陷阱。
3. **FcInput attrs 双份透传**（首轮 e2e 03-14/03-15 失败）：无 `inheritAttrs:false` → 隐式 fallthrough（wrapper div）+ 手动 `v-bind`（内部控件）双份 → `publish-desc-input`/`id` 各出现 2 次 → **Playwright 严格模式对重复 testid 抛错**，被 `confirmPublish()` 的 try/catch 吞掉后走旧弹窗回退超时。修复：`inheritAttrs:false` + 拆分（class/style 留 wrapper 保持布局语义，其余单份落到原生控件——顺带让 label for 关联真正可达）。

## 定位方法论（如实记录）

- 首轮全量回归 4 例失败全部根因在 **SDK 薄封装层**，而非业务替换本身；此前 106 例 e2e 未暴露是因为 FcFormItem/FcInput 此前几乎无表单场景调用。
- **jsdom 完全无法复现 EP 校验行为**（A/B 对照：裸 el-form-item 与 FcFormItem 同样卡 is-validating）——定位只能靠真实浏览器探针 + e2e。
- 页面级探针法也被证伪（HEAD 基线探针同样 0 错误——save 受 loading 门控，点击可能空转）；**唯一可信仪器是 e2e 本身**：HEAD 过 → 工作区挂 → 逐文件二分 → SDK 层根因。
- 过程插曲：vite 对双 `v-bind` 编译报 Duplicate attribute、python 批量编辑断言失败两次，均当场修正。
